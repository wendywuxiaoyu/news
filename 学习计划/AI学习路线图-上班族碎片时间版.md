# AI 学习路线图（原理 + 使用版 · 14 周）

> **定位**：你已经会 Python 基础，不走算法/研究路线。目标是**搞明白原理，并且真的会用**。
> **节奏**：以「周」为单位给目标，不排到每天。每周约 5 小时，可自由拆到碎片时间里。
> **总周期**：14 周（约 3 个半月）。

---

## 一、路线确认

你要的不是"能训练模型"，而是三件事：

1. **看得懂**——听到 embedding、注意力、预训练、RAG、Agent 这些词，知道它在说什么、为什么需要它。
2. **判断得了**——面对一个需求，能判断该用 Prompt、RAG、微调还是干脆不用 AI。
3. **做得出来**——能自己搭一个真正可用的 AI 应用。

所以路线是：**原理地基（3 周）→ 神经网络到 Transformer（3 周）→ 大模型原理与使用（4 周）→ 落地与判断力（4 周）**。跳过数学推导、跳过论文、跳过训练模型，但**不跳过"为什么"**。

---

## 二、原理怎么学：三层解释法

每学一个概念，逼自己回答三个问题，写下来（各 50 字即可）：

| 层次 | 问题 | 举例（embedding） |
|---|---|---|
| 第一层 | **它解决什么问题？** 没有它会怎样？ | 计算机只认数字，没法直接比较"猫"和"狗"像不像 |
| 第二层 | **它大致怎么做到的？** 输入 → 处理 → 输出，不用公式 | 把词映射成一串数字，意思越近，这串数字的方向越接近 |
| 第三层 | **它什么时候会失效？** | 一词多义、领域黑话、训练数据里没见过的概念 |

**能答出第三层，才算真懂。** 只会背第一层，就是"名词党"。

配套两个动作：
- **画图**：任何原理，先画一张"数据怎么流动"的图。
- **讲给别人**：每周挑一个概念，用 3 分钟讲给同事或家人。讲卡住的地方，就是没懂的地方。

---

## 三、使用怎么练：一周一个真实任务

原理靠"解释"，使用靠"用"。每周从你自己的工作里挑一件真实的事，用当周学的东西去做，并记录：

- 用了什么方法
- 效果比不用好多少
- 在哪里翻车

> 不要用"写一首诗""讲个笑话"这类 Demo 练手，那练不出判断力。用你真实要交的活。

## 五、逐周目标

### 阶段一：原理地基（W1–W3）

**W1｜AI 的地形与边界**
- 本周目标：能画出 AI / 机器学习 / 深度学习 / 大模型 的包含关系图。
- 要搞懂：模型不是数据库，是"从数据里压出来的规律"；训练与推理的区别；参数是什么。
- 动手：用 AI 完成 5 件真实工作，记录 2 次它明显出错的案例。
- 过关检验：用 3 分钟讲清"大模型为什么会胡说"。

**W2｜机器学习到底在干什么**
- 本周目标：能说清"特征、标签、损失、泛化"四个词的关系。
- 要搞懂：模型不是记住答案，是找规律；损失函数就是"错得多离谱"的度量；泛化就是"没见过的题也能做"。
- 动手：用 scikit-learn 跑一个分类任务（鸢尾花或泰坦尼克），故意改参数，观察结果怎么变。
- 过关检验：解释"模型学到的是规律，还是死记硬背"，并举一个死记硬背的例子。

**W3｜怎么判断一个模型好不好**
- 本周目标：看懂训练集/验证集/测试集、过拟合、精确率与召回率。
- 要搞懂：为什么不能用训练成绩判断水平；过拟合的三种表现与三种解法；精确率与召回率为什么此消彼长。
- 动手：同一个数据集做三次实验——欠拟合、正常、过拟合，把三条曲线画在一张图上。
- 过关检验：解释"准确率 95% 的模型为什么可能毫无价值"。

> 这三周是整个路线的地基。**后面的 RAG 评估、Prompt 调优，用的全是这套判断标准。**

### 阶段二：神经网络到 Transformer（W4–W6）

**W4｜神经网络怎么学**
- 本周目标：能画出"一个样本从前向传播到参数更新"的完整流程。
- 要搞懂：神经元与激活函数、损失函数、梯度下降、反向传播各自在干嘛（不要公式，要直觉）。
- 动手：看完 3Blue1Brown 神经网络系列；用 sklearn 的 MLP 跑一次，把隐藏层从 1 层加到 3 层看效果。
- 过关检验：用"下山"或"调音量"之类的比喻，把反向传播讲明白。

**W5｜从词到向量：embedding**
- 本周目标：能解释"为什么意思相近的词，向量也相近"。
- 要搞懂：计算机怎么把语言变成数字；相似度怎么算；为什么这是搜索、推荐、RAG 的共同地基。
- 动手：调用一个 embedding 接口，算 10 句话两两之间的相似度，找出"意思近但字面不像"的一对。
- 过关检验：解释"embedding 为什么能解决'关键词搜不到同义词'的问题"。

**W6｜注意力与 Transformer**
- 本周目标：能说出 Transformer 相比之前的模型强在哪。
- 要搞懂：注意力机制在"关注什么"；为什么它能处理长距离依赖；为什么今天所有大模型都是它。
- 动手：画一张 Attention 的数据流图（Q、K、V 从哪来、怎么用），画不出来就回去补。
- 过关检验：解释"一句话里的'它'指代谁，模型是怎么判断的"。

### 阶段三：大模型原理与使用（W7–W10）

**W7｜大模型是怎么造出来的**
- 本周目标：讲清 token → 预训练 → 微调 → 对齐 这条流水线。
- 要搞懂：token 是什么、上下文窗口是什么；预训练学到的是"续写能力"；SFT 与对齐在解决"听话"和"说人话"；温度控制什么。
- 动手：同一个问题，分别用低温度和高温度各问 10 次，记录差异规律。
- 过关检验：解释"为什么大模型本质上是'预测下一个词'，却能回答问题"。

**W8｜Prompt：从玄学到工程**
- 本周目标：把一件重复性工作做成**稳定可复用**的提示模板。
- 要搞懂：结构化提示的要素（角色、任务、输入、约束、输出格式）；few-shot 为什么有效；思维链在什么任务上有用。
- 动手：写一个模板，跑 20 次，统计输出合格率，再改一版对比。
- 过关检验：说出让输出稳定的三个具体手段，并解释每个为什么有效。

**W9｜幻觉与 RAG**
- 本周目标：解释幻觉的成因，并说清 RAG 每一步在解决什么。
- 要搞懂：幻觉不是"bug"，是"预测下一个词"的必然产物；RAG = 先检索再生成；切分、向量化、召回、重排、生成各自的作用。
- 动手：用公开文档做一个最小检索（只做切分 + embedding + 召回，先不生成），看召回准不准。
- 过关检验：解释"RAG 能缓解幻觉，但不能消除幻觉，为什么"。

**W10｜Agent 与三种改造方式的决策**
- 本周目标：给出"什么时候用 Prompt、什么时候用 RAG、什么时候该微调"的判断标准。
- 要搞懂：Agent 就是"模型 + 工具 + 循环"；工具调用怎么工作；微调改的是"风格与格式"，不是"知识"。
- 动手：做一个能调用 1–2 个工具的小助手（查资料、算数、读本地文件）。
- 过关检验：给三个真实需求，分别判断该用哪种方式，并说出理由。

### 阶段四：落地与判断力（W11–W14）

**W11｜搭一个自己的 RAG 知识库**
- 本周目标：跑通端到端问答，并记录 10 个失败案例。
- 动手：灌入自己 20–50 篇文档（工作资料、笔记、手册），做成问答，逐条记录答错的案例。
- 过关检验：能判断一次失败是"没检索到"还是"检索到了但答歪了"。

**W12｜评估与成本：让效果可衡量**
- 本周目标：给你的应用建一个 20 题的评测集，并算出单次成本。
- 要搞懂：为什么"感觉还行"不算数；评测集怎么建；LLM 当裁判的用法与风险；token 成本怎么估。
- 动手：跑评测、记录分数、算每 1000 次调用的花费。
- 过关检验：说出你的系统大概什么水平、瓶颈在检索还是在生成。

**W13｜做成能给人用的东西**
- 本周目标：加上界面、写清 README、处理安全边界。
- 要搞懂：提示注入是什么；哪些数据不能送出去；出错时怎么降级。
- 动手：用 Streamlit 做界面，写 README，找一个没参与的人按文档跑一遍。
- 过关检验：陌生人能独立跑起来，且你知道它不该被用来做什么。

**W14｜复盘与交付**
- 本周目标：完整讲一遍"从数据到大模型到我的应用"的链路。
- 动手：录 1 分钟演示视频；写一页"我原来以为 vs 现在知道"。
- 过关检验：不看稿讲 10 分钟，能回答"如果数据量翻十倍会怎样""如果换成开源模型会怎样"。

## 六、核心概念自测清单

这是"搞明白原理"的验收表。**每个概念，你都要能不看资料回答右边的问题。** 打不了勾的，就是回去补的地方。

**A 组 · 基础（W1–W3）**

| 概念 | 你应该能回答 |
|---|---|
| AI / ML / DL / LLM | 四者是包含关系还是并列关系？各举一例 |
| 参数 | 参数是什么？"70B 模型"的 B 指什么？ |
| 训练 vs 推理 | 哪个费钱？为什么？ |
| 特征 / 标签 | 预测房价时，各是什么？ |
| 损失函数 | 它衡量的是什么？为什么必须要有它？ |
| 过拟合 | 三种表现、三种解法 |
| 训练/验证/测试集 | 为什么要分三份？只用两份会出什么问题？ |
| 精确率 / 召回率 | 垃圾邮件过滤更该看重哪个？为什么？ |

**B 组 · 神经网络（W4–W6）**

| 概念 | 你应该能回答 |
|---|---|
| 神经元 / 激活函数 | 没有激活函数会怎样？ |
| 梯度下降 | "下山"的比喻里，步长对应什么？步长太大会怎样？ |
| 反向传播 | 它在算"谁的责任"，怎么算的？ |
| embedding | 为什么意思近的向量也近？维度代表什么？ |
| 注意力机制 | 它在决定"看哪里"？怎么决定？ |
| Transformer | 相比 RNN 的核心优势是什么？ |

**C 组 · 大模型（W7–W10）**

| 概念 | 你应该能回答 |
|---|---|
| token | 中文一个词大概几个 token？为什么按 token 收费？ |
| 上下文窗口 | 超了会怎样？为什么不能无限大？ |
| 温度 | 调高调低分别适合什么任务？ |
| 预训练 | 它到底学会了什么能力？ |
| SFT / 对齐 | 分别解决"不会做"还是"不好好做"？ |
| 幻觉 | 三个成因，以及为什么无法根除 |
| Prompt / few-shot | few-shot 为什么有效？给几个例子最合适？ |
| 思维链 | 哪些任务上有效，哪些上没用？ |

**D 组 · 应用（W11–W14）**

| 概念 | 你应该能回答 |
|---|---|
| RAG | 五个环节，各自的失败会导致什么现象？ |
| 向量检索 | 为什么比关键词检索更能找到同义表达？它的短板是什么？ |
| Agent / 工具调用 | Agent 和"一个很长的 Prompt"本质区别在哪？ |
| 微调 | 它改的是知识还是风格？什么情况下值得做？ |
| 评测集 / LLM 当裁判 | 为什么必须自己建评测集？裁判模型会有什么偏差？ |
| 提示注入 | 攻击者怎么利用它？怎么防？ |

## 七、四个针对"原理学习者"的坑

1. **只背名词，不答第三层**——能说出"注意力机制"四个字，但讲不出它什么时候失效。用第二节的三层解释法自查。
2. **跳过评估直接学大模型**——不理解"怎么算好"，后面调 Prompt 全靠感觉。
3. **把 Prompt 当玄学**——写提示不是求神拜佛，是有结构的工程：角色、任务、约束、格式、例子。
4. **只看不做**——原理看懂了，一动手发现全是细节问题。每周那个"真实任务"不能省。

## 十一、怎么持续跟进：三层信息架构

"AI 变化太快"是真的，但**变化快的是哪一层，这决定了你该怎么跟**。

| 层 | 内容 | 变化速度 | 你的动作 |
|---|---|---|---|
| 原理层 | Transformer、梯度下降、RAG 链路、评估方法 | 5–10 年才动一次 | 跟完 14 周，之后不用追 |
| 能力层 | 模型能做什么（多模态、长上下文、推理、Agent 能力） | 3–6 个月一变 | 每月扫一次，够用 |
| 工具层 | 框架、API、产品名、价格 | 每周都在变 | 只在要用时查，不主动追 |

**核心判断**：你担心的"过期"，过期的是工具层（某个框架怎么调）；你 14 周学的是原理层 + 能力层。所以**这份计划不会过期**，过期的是"某某工具的用法"，而那部分本来就应该用的时候现查。

### 信息源（5 个就够，多了就是负担）

| 类型 | 具体 | 看什么 |
|---|---|---|
| 实操追踪 | Simon Willison 的博客 | 英文，更新极快，偏工程，经常有可直接用的判断 |
| 行业周报 | 吴恩达《The Batch》 | 每周一封，行业 + 研究，篇幅可控 |
| 工程深度 | Latent Space（播客/通讯） | 英文，讲工程实现，碎片时间适合听 |
| 一手发布 | OpenAI / Anthropic / Google DeepMind / DeepSeek 官方博客 | 只看"发布了什么、能力变了什么"，不看二手解读 |
| 中文雷达 | 机器之心 或 量子位（选一个） | 只当"发生了什么"的雷达，**不当学习材料** |

### 每周日 30 分钟的"扫读三问"

1. 这周有没有**能力边界**的变化？（原来做不到的事，现在能做了）
2. 有没有**价格或速度**的变化？（会改变你的方案选择）
3. 我正在学的哪个概念被推翻了？（极少，一年也就一两次）

把答案记进一个「变化日志」：**每月只留 3 条**。一年 36 条，比刷一万条新闻有用，因为它是你判断"什么真的变了"的依据。

### 三条不做

- 不追每日新闻（每周 30 分钟足够，再多是焦虑不是信息）
- 不追新框架名词（概念稳定，工具会换）
- 不追榜单排名（榜单分数和"能不能用"是两件事）

### 用 AI 过滤信息

每篇文章丢给 AI，只问三个固定问题：
1. 它改变了什么能力？
2. 对我这种"会用 AI 的人"意味着什么？
3. 证据是什么，是不是厂商自夸？

这就是"用自己的工具学自己的领域"，也是你学习的一部分。

## 十二、我们怎么配合：分工与任务卡

### 分工表

| 事项 | 谁负责 |
|---|---|
| 定路线、排周次 | 我 |
| 选资源、指到具体章节（"只看到第 3 章"） | 我 |
| 每周讲解概念（讲原理 + 类比 + 画图） | 我 |
| 设计任务卡和验收标准 | 我 |
| 动手、踩坑、记录失败案例 | **你** |
| 提问、把学到的讲给我听 | **你** |
| 批改、纠偏、给下一版 | 我 |

**结论：你不需要自己找资源。** 找资源是最消耗动机的环节，也是最该由我承担的环节。你只需要做两件不可替代的事：**动手**，和**讲给我听**。

### 应用部分：我带

| 模式 | 适合什么 | 缺点 |
|---|---|---|
| 自己找案例 | 找灵感 | 案例和你的场景不匹配，抄完还是不会用 |
| 跟着教程抄一遍 | 学工具用法 | 教程把坑都填好了，你学不到判断力 |
| **我给骨架 + 你填业务 + 我批改**（推荐） | 建立判断力 | 需要你拿真实资料出来 |

### 任务卡的样子（以 W11 为例）

**任务卡 01：你的第一版知识库问答**

- **目标**：用手头 20–50 篇真实文档，做一个能答对七成问题的问答。
- **输入**：你自己的资料（工作文档、笔记、手册）。
- **交付**：能跑的脚本 + 10 条测试问题 + 每条的判定记录。
- **验收**：你能指出每个错误是"没检索到"还是"答歪了"。
- **常见坑**：切分太大或太小；只取 top1 结果；把整篇文档塞进上下文。
- **我怎么评**：只看你的错误分类准不准，不看你用了哪个框架。
